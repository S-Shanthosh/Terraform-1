## 🚀 Quickstart — Fresh AWS Account

```bash
# 1. Clone
git clone https://github.com/S-Shanthosh/Terraform-1.git workspace

# 2. Bootstrap (run ONCE per account)
chmod +x ~/workspace/setup/bootstrap.sh
~/workspace/setup/bootstrap.sh
```

> 💬 You'll be asked **one question** — your state bucket name. Everything else is fully automatic.

---

## 🧠 What Bootstrap Does — Step by Step

```
bootstrap.sh
│
├── 📍 Auto-detects repo path          (works regardless of clone folder name)
├── ⬇️  Installs Terraform 1.7.5       (skips if already present)
├── 🔧  Configures .bashrc             (idempotent — safe to run multiple times)
├── 🪣  Creates S3 state bucket        (versioned, encrypted, public-access blocked)
├── 🔒  Creates DynamoDB lock table    (prevents concurrent state corruption)
├── 🔑  Generates SSH key pair         (for EC2 access from CloudShell)
├── 📝  Writes backend.tf dynamically  (wired to your bucket automatically)
├── 🔐  Sets permissions on scripts    (no more permission denied errors)
├── 🚀  Runs terraform init            (providers downloaded and cached)
└── 💾  Saves session to S3            (so next login restores in seconds)
```

---

## 🔄 Every New CloudShell Session

CloudShell resets `/tmp` on every login. This setup **auto-restores** everything on session start — no manual steps needed.

```
On Login (automatic via .bashrc)
│
├── ⬇️  Restores Terraform binary from S3
├── 📦  Restores provider plugins      (skips terraform init!)
└── 🔑  Restores SSH keys
```

| When | Command |
|------|---------|
| 🟢 Session starts | **Automatic** — nothing to run |
| 🔴 Before exiting | `$TF_SETUP_DIR/tf-save.sh` |

## 🔑 SSH Key

Bootstrap auto-generates an RSA 4096-bit key at:


View your public key anytime:

## 🛠️ Deploy Infrastructure

```bash
cd ~/workspace/Infra

# Plan (dry run)
terraform plan -var-file=environments/dev/dev.tfvars

# Apply
terraform apply -var-file=environments/dev/dev.tfvars

# Destroy
terraform destroy -var-file=environments/dev/dev.tfvars
```

> ⏰ **Auto-destroy** is enabled — any `terraform apply` will automatically destroy resources after **1 hour** to prevent runaway costs.

## 🔁 Idempotency — Safe to Run Multiple Times

| Step | Protection Mechanism |
|------|---------------------|
| Terraform install | Version check before download |
| `.bashrc` config | Sentinel `# __TF_BOOTSTRAP_DONE__` |
| S3 bucket | `head-bucket` existence check |
| DynamoDB table | `describe-table` existence check |
| SSH key | File existence check |

## 🧹 Full Teardown

```bash
# Delete state bucket
aws s3 rm s3://<your-bucket> --recursive
aws s3api delete-bucket --bucket <your-bucket> --region ap-south-1

# Delete DynamoDB lock table
aws dynamodb delete-table --table-name <your-bucket>-locks --region ap-south-1

# Clean local environment
rm -rf ~/workspace ~/bin/terraform /tmp/.terraform
rm -f ~/.ssh/shanthosh-key ~/.ssh/shanthosh-key.pub

# Clean .bashrc
sed -i '/# __TF_BOOTSTRAP_DONE__/,$ d' ~/.bashrc
```

## ⚠️ Important Notes

- 🔐 **IAM Permissions** — Terraform inherits your CloudShell IAM role. Verify with `aws sts get-caller-identity`
- 🌏 **Region** — Hardcoded to `ap-south-1`. Change `REGION` in `bootstrap.sh` if needed
- 💰 **Cost** — Auto-destroy kicks in after 1 hour on every `apply` to prevent surprise bills
- 🔄 **Multi-account** — Run `bootstrap.sh` once per AWS account. Each account gets its own state bucket
